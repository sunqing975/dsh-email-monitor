# 163 新邮件会话监控（本地扩展版）

基于 MIT 开源项目 https://github.com/STARDUSTLC666/dsh-email 的 0.24.0 扩展；保留上游 LICENSE。本地版本 0.24.0-monitor.1，包名 `dsh-email-monitor`。基础邮箱接入继承上游多品牌能力；本说明中的后台自动监控首期仅开放 163 IMAP。禁用上游自动更新注册，避免本地监控扩展被官方版本覆盖。

## 配置

1. 安装本地构建包后，在 DSH 设置的邮件账户页面添加账户，provider 选 `163`，填写完整邮箱地址和 **IMAP 授权码**。在网易邮箱网页设置中先开启 IMAP/SMTP 服务。授权码不要发到聊天里。
2. 测试连接。163 接收服务器为 `imap.163.com:993`，使用 TLS。
3. 在“邮箱设置”的“新邮件监控”填写账户、目录与检查间隔，启用后点击“保存监控设置”。控件写入插件配置的 `tool-email` 条目（启用项为 `incomingMonitorEnabled`）。`incomingMonitorAccount` 留空使用默认账户；多账户建议填明确的账户名称。`incomingMonitorFolder` 默认 `INBOX`；`incomingMonitorPollSeconds` 默认 60 秒，范围 30–3600；`incomingMonitorCwd` 建议填写希望新会话使用的工作目录。
4. 首次成功检查建立基线，不处理历史邮件。此后新收到的邮件自动创建普通 DSH 会话，生成中文摘要、待办和建议回复文本。是否已读不影响检测。收件内容将交给当前配置的模型处理。

监控在 Host 后台运行，不依赖浏览器打开；DSH 主进程需要运行且网络可用。电脑休眠期间不会实时检测，恢复后继续检查。模型账户必须已配置。监控不会自动发送回复，不实现 IM 通知，不自动下载附件；附件仅根据元数据说明，正文超长会注明截断。上游已有“邮件任务”是另一种通过邮件下达命令的功能，本次不启用它。

状态和游标保存在 DSH storage 的插件独立 KV 单元中，不存邮箱密码或邮件正文；原始正文及模型结果会进入新建会话的常规持久记录。断线会继续重试。邮箱 UIDVALIDITY 改变时重新建立基线；这类服务器重建期间需要人工核对邮件。切换账户或文件夹会有独立基线。

## 已有邮件生成回复建议

在“邮件”页选择已有邮件，点击“生成回复建议”。插件创建普通 DSH 对话，输出摘要、待办与回复示例并跳转到该会话；可继续对话调整措辞。此操作与自动监控复用同一提示，不发送邮件、不修改邮箱内容。失败后可在当前详情中重试，同一次操作复用请求编号和已创建的会话；请求去重表在插件重载后重置，每次运行最多接纳 512 个不同的手动请求。保留的会话工具为邮件列表、阅读、搜索、文件夹、配置自检和 `email_suggest_reply`。

界面提供“邮件”“邮箱设置”和“处理记录”，不再启用发送、草稿、定时发送、规则、邮件任务和邮箱修改入口。已有账号配置与授权信息保留。

## 处理记录与排障

“处理记录”显示监听状态、最近和下次检查时间，以及自动和手动调用 DSH 的记录。记录按请求编号更新，持久保存最近 500 条；页面显示最近 100 条，每 10 秒刷新。只记录账户名、文件夹、UID、状态和会话编号，不保存正文或授权码。`email_activity` 可在对话中读取近期记录。

“已提交”表示请求已被 DSH 接收并完成持久化检查，不代表模型已生成回复。点击“打开关联会话”查看结果；会话被移除时只提示，处理记录继续保留。失败记录不显示可能含敏感信息的底层错误原文。首次基线会明确记录跳过历史邮件；启用监控后应先确认出现成功检查，再发送测试邮件。

## 页面加载修复

本地扩展关闭上游自动更新注册后，同步移除页面中依赖构建注入的 `__stardustUpdatesGuard` 调用，避免打开邮件工作台时因函数未定义而崩溃。修改后须重新构建客户端并重新加载插件；已崩溃的页面可刷新后重新打开。

邮件详情的图文/纯文本切换按钮已移除对未声明的 `working`、`busy` 变量的引用，避免含图文正文的邮件打开时发生渲染异常；正文切换不依赖发信或附件操作状态。

## 验证方式

本地测试覆盖首次基线、已读的新邮件、重启恢复、失败重试、UIDVALIDITY 变化及批量收件；构建检查和上游回归测试单独运行。真实 163 登录和端到端收件须在配置用户授权码后验证。

### 企业内部邮箱自动监听适配（待实施）

当前自定义 IMAP 邮箱可复用已有账户接入、列表和阅读能力；自动监听仍限制为 163，企业邮箱需要完成以下适配与真实收件验证后再开放，不能仅移除服务器白名单就视为支持。

1. **确认接入信息**：由企业 IT 提供邮箱系统类型、IMAP 服务地址与端口、TLS 要求、认证方式、可监听文件夹，以及是否必须通过内网或 VPN 访问。授权码和令牌只进入安全配置，不写入文档或日志。
2. **标准 IMAP 优先**：支持 IMAP 的企业邮箱使用自定义服务器配置；将监听资格从 163 主机限制改为经过验证的协议能力，复用 UID/UIDVALIDITY 游标、重试和去重。验证服务器差异、已读邮件检测、批量收件及重启恢复。
3. **认证与证书**：分别适配密码/授权码、OAuth2/企业 SSO。企业私有 CA 通过受信任证书链配置接入，保留 TLS 证书校验；验证令牌过期刷新与失效提示。DSH 主机需具备内网/VPN 连通性。
4. **非 IMAP 系统**：Microsoft 365 在获准使用 Microsoft Graph 时可新增 Graph 适配；仅开放 Exchange EWS 或厂商 API 的系统按实际支持情况单独适配。浏览器可登录不代表可直接监听；没有开放协议/API 时需企业 IT 提供集成入口。
5. **数据边界与验收**：确认公司允许邮件内容进入所配置的模型及 DSH 会话；有内网要求时使用获准的内网部署和模型。用测试账号验证“收件 → 自动提交 → 摘要/回复建议 → 处理记录 → 关联会话”，并覆盖断网恢复、认证失败、重复检测及会话删除后的提示。
